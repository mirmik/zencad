# Building the ZenCad manual

The bilingual source lives in `ru/*.md`: `:ru` and `:en` select language blocks,
`::` resumes shared content. Indentation inside code fences is preserved. Navigation
is in `ru/nav.md` and `en/nav.md`; generated HTML lives in `docs/ru` and `docs/en`.

From the repository root, in a development environment:

```sh
python -m pip install markdown2 pygments
python mangen/main.py
python mangen/main.py update
python mangen/check.py
```

The first build writes `mangen/build`, the second updates `docs`. Use `--output PATH`
for a disposable preview. No CAD scripts, image generation or viewer startup run
during documentation generation. Existing `docs/images` assets are reused.

The check requires the project's geometry dependencies. It validates local HTML
links and anchors, runs both languages' current Python examples in temporary
directories, exercises their managed animations, and checks the documented
inspect/check commands. It does not open a viewer or claim native render coverage.

`EXAMPLE_PAGES` in `main.py` selects pages whose complete Python snippets are
executed by the documentation smoke check. It does not classify the remaining
manual as obsolete. Preserve the full thematic navigation, detailed operation
reference and illustrations when updating content. Pages without a current
Markdown source retain their URLs and receive the same navigation. Keep both
navigation files synchronized and place migration last.

Development contracts in `docs/development` are maintained directly and are not
generated by this tool. Historical migration checkpoints should stay explicitly
historical; update active references when the public API changes.
